# Claude Chat v5 — Images In and Out Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Attach images to messages (paste, drop, 📎 picker) and see images in the chat — your own attachments as thumbnails, images Claude reads with its Read tool, and local project images referenced in Claude's markdown — while remote images stay blocked.

**Architecture:** A new pure package `claudechat.image` validates image bytes by magic bytes, reads dimensions from headers, and downscales/re-encodes with `javax.imageio` (`Images`), holds a chat's pending attachments (`PendingAttachments`) and reassembles chunked uploads from the page (`Uploads`). The page sends pasted/dropped files to Kotlin as base64 in 256 Ki-character chunks over the existing `JBCefJSQuery` bridge; Kotlin validates and downscales off the EDT, keeps the bytes only until the message is written to the CLI, and gives the page small `data:` thumbnails. `CliMessages.userContent` writes the probe-verified content array (text block, then image blocks); `CliParser` reads image blocks inside `tool_result.content` and `ChatSession` turns them into display copies on the tool row. Markdown images become unguessable text markers in the `marked` renderer, survive DOMPurify (which still forbids `img`) as text, become alt-text spans, and are swapped for page-created `<img>` elements once `FileLinker.localImage` (FileLinker's containment rules, off the EDT) answers a new `resolveImages` bridge message.

**Tech Stack:** Kotlin 2.4.21, IntelliJ Platform Gradle Plugin 2.19.0, WebStorm 2026.2.3 (build 262) via `local(...)`, JBR 25 (`javax.imageio`, `java.awt.image`), JCEF 144 (`JBCefJSQuery`), platform-bundled `kotlinx.serialization.json` (element API only), marked 15.0.12, DOMPurify 3.2.6, JUnit 4 + `BasePlatformTestCase`.

**Spec:** `docs/superpowers/specs/2026-11-03-images-design.md` (extends `docs/superpowers/specs/2026-11-03-editor-context-design.md`, `docs/superpowers/specs/2026-11-03-follow-chat-checkout-design.md`, `docs/superpowers/specs/2026-11-03-multi-chat-worktrees-design.md` and `docs/superpowers/specs/2026-11-03-claude-chat-webstorm-design.md`; everything there still applies unless v5 changes it).

## Verified platform facts (checked with throw-away probes in a scratch clone; nothing kept)

- `javax.imageio` in plain JBR 25.0.4 reads and writes `png, jpeg, gif, bmp, wbmp, tiff` — **no WebP**. Inside the IDE (and in `BasePlatformTestCase` tests) the bundled, enabled-by-default plugin `intellij.webp` (`plugins/webp`, `<imageReaderWriterSpi>` extensions `com.android.tools.adtui.webp.WebpImageReaderSpi`/`WebpImageWriterSpi`) registers WebP into ImageIO: `ImageIO.getImageReadersByMIMEType("image/webp").hasNext()` is true, `ImageIO.write(img, "webp", out)` writes a `RIFF…WEBPVP8L` file and `ImageIO.read` reads it back (30×20 probe). Decision: `Images.webpDecodable` checks for a registered reader at run time; with one, WebP that needs scaling is decoded and re-encoded as PNG (then JPEG) exactly like GIF; without one (bare JVM, or the WebP plugin disabled), WebP is accepted as-is when ≤ 5 MB and ≤ 2000 px (dimensions parsed from its `VP8 `/`VP8L`/`VP8X` header) and otherwise refused with a notice. The plugin never references the WebP plugin's classes (no dependency). Pure tests force `webpDecodable = { false }`; `ImagesWebpTest` (platform test) covers the IDE reader.
- `ImageReader.getWidth(0)/getHeight(0)` read only the header (a PNG whose IHDR claims 10000×10000 reports that size without decoding), so the 40-megapixel decode guard runs before any pixel allocation.
- JCEF is 144.0.15 (Chromium 144) and the IDE can run it out of process (`ide.browser.jcef.out-of-process.enabled`) over a Thrift transport with `TConfiguration` message/frame-size limits; `JBCefJSQuery` itself has no size check. Decision: page→IDE image bytes go in chunks of 262144 base64 characters (`attachStart` / `attachChunk`… / `attachEnd`), each decoded on arrival, total capped at 20 MB; IDE→page history (`reset`) is split into ≤ 2 000 000-character batches (`reset` + `items`), and every image the page gets is a display copy ≤ 512 KB (thumbnails ≤ 64 KB). Bridge messages from one page are handled in order (one `invokeLater` per message).
- `FileChooserDescriptorFactory.createMultipleFilesNoJarsDescriptor().withExtensionFilter("Images", "png", "jpg", "jpeg", "gif", "webp").withTitle("Attach Images")` and `FileChooser.chooseFiles(descriptor, project, null) { files -> … }` compile against 262 without deprecation warnings.
- marked 15.0.12: `marked.use({ renderer: { image(token) { … } } })` gets the **raw** `token.href` (before marked's `encodeURI` cleaning) and `token.text` (alt); `` `![no](a.png)` `` in a code span produces no image token; a linked image `[![logo](./l.png)](https://x)` yields the marker inside the `<a>` text. Checked with node against the vendored file.
- Light-test files are in `temp://`, so an absolute path to them does not resolve through `LocalFileSystem` (same as v2 `resolve`); absolute-path behaviour is tested with a real temp dir and `VfsRootAccess.allowRootAccess`.

## Memory policy

- Attachment bytes live in Kotlin only from upload until the message line is written to the CLI (`PendingAttachments` → `Chat` outbox → `ChatSession` queue line). The page never keeps the full image; it keeps nothing after sending.
- Chat history (`ChatItem`) keeps only small `data:` URLs: bubble thumbnails (long edge ≤ 160 px, ≤ 64 KB each, ≤ 10 per message) and tool-result display copies (≤ 800 px, ≤ 512 KB each). Local markdown images are not stored at all: the page asks again whenever it re-renders a finished reply.
- Resumed transcripts never load image data (`[image]` placeholders).

```kotlin
package claudechat.testutil

import java.awt.Color
import java.awt.image.BufferedImage
import java.io.ByteArrayOutputStream
import java.util.Base64
import java.util.Random
import javax.imageio.ImageIO

/** Image bytes for tests. */
object TestImages {
    /** The 4x4 blue PNG Claude's Read tool returned in the protocol probe (73 bytes). */
    const val BLUE_PNG_BASE64 = "iVBORw0KGgoAAAANSUhEUgAAAAQAAAAECAIAAAAmkwkpAAAAEElEQVR4nGNgYPiPhIjiAACOsw/xs6MvMwAAAABJRU5ErkJggg=="

    /** The 4x4 red PNG the probe sent as an image block. */
    const val RED_PNG_BASE64 = "iVBORw0KGgoAAAANSUhEUgAAAAQAAAAECAIAAAAmkwkpAAAAEElEQVR4nGP4z8AARwzEcQCukw/x0F8jngAAAABJRU5ErkJggg=="

    fun bytes(base64: String): ByteArray = Base64.getDecoder().decode(base64)

    /** A one-colour image in an ImageIO format ("png", "jpeg", "gif"). */
    fun solid(w: Int, h: Int, format: String = "png", color: Color = Color.BLUE): ByteArray {
        val img = BufferedImage(w, h, if (format == "png") BufferedImage.TYPE_INT_ARGB else BufferedImage.TYPE_INT_RGB)
        val g = img.createGraphics()
        g.color = color
        g.fillRect(0, 0, w, h)
        g.dispose()
        return ByteArrayOutputStream().also { check(ImageIO.write(img, format, it)) }.toByteArray()
    }

    /** A PNG of random pixels: PNG can't compress it, JPEG can. */
    fun noise(w: Int, h: Int, seed: Long = 1): ByteArray {
        val img = BufferedImage(w, h, BufferedImage.TYPE_INT_RGB)
        val random = Random(seed)
        for (y in 0 until h) for (x in 0 until w) img.setRGB(x, y, random.nextInt(0x1000000))
        return ByteArrayOutputStream().also { ImageIO.write(img, "png", it) }.toByteArray()
    }

    /** The first 30 bytes of a WebP file of the given chunk kind ("VP8 ", "VP8L" or "VP8X") and size; enough for its header. */
    fun webpHeader(kind: String, w: Int, h: Int): ByteArray {
        val b = ByteArray(30)
        fun ascii(at: Int, s: String) = s.forEachIndexed { i, c -> b[at + i] = c.code.toByte() }
        fun le(at: Int, value: Long, n: Int) = repeat(n) { i -> b[at + i] = (value shr (8 * i)).toByte() }
        ascii(0, "RIFF"); le(4, 22, 4); ascii(8, "WEBP"); ascii(12, kind); le(16, 10, 4)
        when (kind) {
            "VP8 " -> { b[23] = 0x9D.toByte(); b[24] = 0x01; b[25] = 0x2A; le(26, w.toLong(), 2); le(28, h.toLong(), 2) }
            "VP8L" -> { b[20] = 0x2F; le(21, (w - 1).toLong() or ((h - 1).toLong() shl 14), 4) }
            "VP8X" -> { le(24, (w - 1).toLong(), 3); le(27, (h - 1).toLong(), 3) }
        }
        return b
    }
}
```

```kotlin
package claudechat.image

import claudechat.testutil.TestImages
import org.junit.After
import org.junit.Assert.assertArrayEquals
import org.junit.Assert.assertEquals
import org.junit.Assert.assertNull
import org.junit.Assert.assertSame
import org.junit.Assert.assertTrue
import org.junit.Before
import org.junit.Test

/** Runs as if no WebP reader were installed (the bare JDK); `ImagesWebpTest` covers the IDE's WebP reader. */
class ImagesTest {
    private lateinit var savedWebp: () -> Boolean

    @Before fun noWebpReader() {
        savedWebp = Images.webpDecodable
        Images.webpDecodable = { false }
    }

    @After fun restoreWebpReader() {
        Images.webpDecodable = savedWebp
    }

    private fun ok(p: Prepared): Image = (p as? Prepared.Ok)?.image ?: error("expected Ok, got ${(p as Prepared.Rejected).reason}")
    private fun reason(p: Prepared): String = (p as? Prepared.Rejected)?.reason ?: error("expected Rejected")

    @Test fun sniffsMagicBytesOnly() {
        assertEquals(ImageType.PNG, ImageType.sniff(TestImages.bytes(TestImages.BLUE_PNG_BASE64)))
        assertEquals(ImageType.JPEG, ImageType.sniff(TestImages.solid(2, 2, "jpeg")))
        assertEquals(ImageType.GIF, ImageType.sniff(TestImages.solid(2, 2, "gif")))
        assertEquals(ImageType.WEBP, ImageType.sniff(TestImages.webpHeader("VP8L", 1, 1)))
        assertNull(ImageType.sniff("hello world".toByteArray()))
        assertNull(ImageType.sniff(ByteArray(0)))
        assertNull(ImageType.sniff("RIFF\u0000\u0000\u0000\u0000WAVE".toByteArray()))
    }

    @Test fun dimensionsComeFromTheHeader() {
        assertEquals(4 to 4, Images.dimensions(TestImages.bytes(TestImages.BLUE_PNG_BASE64), ImageType.PNG))
        assertEquals(30 to 20, Images.dimensions(TestImages.solid(30, 20, "jpeg"), ImageType.JPEG))
        assertEquals(7 to 3, Images.dimensions(TestImages.solid(7, 3, "gif"), ImageType.GIF))
        assertEquals(640 to 480, Images.dimensions(TestImages.webpHeader("VP8 ", 640, 480), ImageType.WEBP))
        assertEquals(3000 to 17, Images.dimensions(TestImages.webpHeader("VP8L", 3000, 17), ImageType.WEBP))
        assertEquals(5000 to 4000, Images.dimensions(TestImages.webpHeader("VP8X", 5000, 4000), ImageType.WEBP))
        assertNull(Images.dimensions(TestImages.bytes(TestImages.BLUE_PNG_BASE64).copyOf(12), ImageType.PNG))
    }

    @Test fun smallImagesAreSentAsTheyAre() {
        val bytes = TestImages.bytes(TestImages.BLUE_PNG_BASE64)
        val image = ok(Images.prepare(bytes))
        assertSame(bytes, image.bytes)
        assertEquals(ImageType.PNG, image.type)
        assertEquals("data:image/png;base64,${TestImages.BLUE_PNG_BASE64}", image.dataUrl())
        assertEquals(TestImages.BLUE_PNG_BASE64, image.base64())
        assertEquals(ImageType.WEBP, ok(Images.prepare(TestImages.webpHeader("VP8X", 2000, 1000))).type)
    }

    @Test fun aLongEdgeOver2000IsScaledDownKeepingTheFormat() {
        val png = ok(Images.prepare(TestImages.solid(3000, 1500)))
        assertEquals(ImageType.PNG, png.type)
        assertEquals(2000 to 1000, png.width to png.height)
        assertEquals(2000 to 1000, Images.dimensions(png.bytes, ImageType.PNG))
        val jpeg = ok(Images.prepare(TestImages.solid(1000, 2400, "jpeg")))
        assertEquals(ImageType.JPEG, jpeg.type)
        assertEquals(833 to 2000, jpeg.width to jpeg.height)
    }

    @Test fun gifIsReencodedAsPngWhenItNeedsScaling() {
        val image = ok(Images.prepare(TestImages.solid(2500, 100, "gif")))
        assertEquals(ImageType.PNG, image.type)
        assertEquals(2000 to 80, image.width to image.height)
    }

    @Test fun pngThatStaysTooLargeBecomesJpeg() {
        val noise = TestImages.noise(300, 300)
        assertTrue(noise.size > 200_000)
        val image = ok(Images.prepare(noise, maxBytes = 200_000))
        assertEquals(ImageType.JPEG, image.type)
        assertEquals(300 to 300, image.width to image.height)
        assertTrue(image.bytes.size <= 200_000)
    }

    @Test fun rejections() {
        assertEquals(Images.NOT_AN_IMAGE, reason(Images.prepare("not an image".toByteArray())))
        assertEquals(Images.UNREADABLE, reason(Images.prepare(TestImages.bytes(TestImages.BLUE_PNG_BASE64).copyOf(12))))
        assertEquals(Images.WEBP_TOO_LARGE, reason(Images.prepare(TestImages.webpHeader("VP8X", 2001, 10))))
        assertEquals(Images.TOO_MANY_PIXELS, reason(Images.prepare(claimSize(TestImages.solid(1, 1)))))
        assertEquals(Images.TOO_LARGE, reason(Images.prepare(TestImages.noise(300, 300), maxBytes = 100)))
```

```kotlin
package claudechat.image

import java.awt.Color
import java.awt.RenderingHints
import java.awt.image.BufferedImage
import java.io.ByteArrayInputStream
import java.io.ByteArrayOutputStream
import java.util.Base64
import javax.imageio.IIOImage
import javax.imageio.ImageIO
import javax.imageio.ImageWriteParam
import kotlin.math.max
import kotlin.math.roundToInt

/** The image formats the chat accepts. Always decided by the bytes, never by a file name or a reported MIME type. */
enum class ImageType(val mime: String) {
    PNG("image/png"),
    JPEG("image/jpeg"),
    GIF("image/gif"),
    WEBP("image/webp");

    companion object {
        fun sniff(b: ByteArray): ImageType? = when {
            b.has(0, 0x89, 0x50, 0x4E, 0x47, 0x0D, 0x0A, 0x1A, 0x0A) -> PNG
            b.has(0, 0xFF, 0xD8, 0xFF) -> JPEG
            (b.has(0, 'G', 'I', 'F', '8', '7', 'a') || b.has(0, 'G', 'I', 'F', '8', '9', 'a')) -> GIF
            b.has(0, 'R', 'I', 'F', 'F') && b.has(8, 'W', 'E', 'B', 'P') -> WEBP
            else -> null
        }
    }
}

/** Image bytes whose [type] was checked by magic bytes. */
class Image(val type: ImageType, val bytes: ByteArray, val width: Int, val height: Int) {
    fun base64(): String = Base64.getEncoder().encodeToString(bytes)
    fun dataUrl(): String = "data:${type.mime};base64,${base64()}"
}

sealed interface Prepared {
    class Ok(val image: Image) : Prepared
    class Rejected(val reason: String) : Prepared
}

/** Validation, downscaling and re-encoding of images (pure: no IDE API). */
object Images {
    const val MAX_PER_MESSAGE = 10
    const val MAX_BYTES = 5 * 1024 * 1024
    const val MAX_EDGE = 2000
    /** Largest raw input (before downscaling) the plugin reads from the page or a picked file. */
    const val MAX_INPUT_BYTES = 20 * 1024 * 1024
    /** Never decode more pixels than this (about 160 MB of ARGB): a small file can claim a huge canvas. */
    const val MAX_PIXELS = 40_000_000L
    const val THUMB_EDGE = 160
    const val THUMB_BYTES = 64 * 1024
    const val PREVIEW_EDGE = 800
    const val PREVIEW_BYTES = 512 * 1024
    const val JPEG_QUALITY = 0.85f

    const val NOT_AN_IMAGE = "not a PNG, JPEG, GIF or WebP image"
    const val UNREADABLE = "the image can't be read"
    const val TOO_MANY_PIXELS = "the image is too large to process"
    const val WEBP_TOO_LARGE = "WebP images over 5 MB or 2000 px can't be downscaled here"

    /**
     * Whether `ImageIO` can decode WebP in this JVM. The JDK cannot; inside the IDE the bundled WebP plugin
     * (`intellij.webp`) registers a reader. Without one, WebP is only ever passed through as it is. Tests replace it.
     */
    @Volatile internal var webpDecodable: () -> Boolean = { ImageIO.getImageReadersByMIMEType("image/webp").hasNext() }
    const val TOO_LARGE = "it can't be brought under 5 MB"

    /** Width and height from the header, without decoding pixels; null when the header can't be read. */
    fun dimensions(bytes: ByteArray, type: ImageType): Pair<Int, Int>? =
        if (type == ImageType.WEBP) webpDimensions(bytes) else try {
            ImageIO.createImageInputStream(ByteArrayInputStream(bytes))?.use { stream ->
                val reader = ImageIO.getImageReaders(stream).asSequence().firstOrNull() ?: return null
                try {
                    reader.input = stream
                    reader.getWidth(0) to reader.getHeight(0)
                } finally {
                    reader.dispose()
                }
            }
        } catch (e: Exception) {
            null
        }

    /**
     * An image ready to send to Claude: as it is when it is at most [maxBytes] and its long edge at most [maxEdge];
     * otherwise scaled to fit [maxEdge] (aspect kept) and re-encoded — JPEG stays JPEG (quality 0.85), PNG/GIF become
     * PNG and fall back to JPEG when still too large. WebP is scaled like GIF when [webpDecodable], else refused.
     */
    fun prepare(bytes: ByteArray, maxBytes: Int = MAX_BYTES, maxEdge: Int = MAX_EDGE): Prepared {
        val type = ImageType.sniff(bytes) ?: return Prepared.Rejected(NOT_AN_IMAGE)
        val (w, h) = dimensions(bytes, type) ?: return Prepared.Rejected(UNREADABLE)
        if (bytes.size <= maxBytes && max(w, h) <= maxEdge) return Prepared.Ok(Image(type, bytes, w, h))
        if (type == ImageType.WEBP && !webpDecodable()) return Prepared.Rejected(WEBP_TOO_LARGE)
        if (w.toLong() * h > MAX_PIXELS) return Prepared.Rejected(TOO_MANY_PIXELS)
        val source = decode(bytes) ?: return Prepared.Rejected(UNREADABLE)
        return fit(source, type, maxEdge, maxBytes)?.let { Prepared.Ok(it) } ?: Prepared.Rejected(TOO_LARGE)
    }

    /**
     * A copy to show in the chat: the bytes themselves when they fit [maxBytes] and [maxEdge] (an undecodable WebP:
     * when it fits [maxBytes]; the page scales it), otherwise a scaled re-encoding as in [prepare]; null when nothing fits.
     */
    fun preview(bytes: ByteArray, maxEdge: Int = PREVIEW_EDGE, maxBytes: Int = PREVIEW_BYTES): Image? {
        val type = ImageType.sniff(bytes) ?: return null
        val (w, h) = dimensions(bytes, type) ?: return null
        val undecodable = type == ImageType.WEBP && !webpDecodable()
        if (bytes.size <= maxBytes && (undecodable || max(w, h) <= maxEdge)) return Image(type, bytes, w, h)
        if (undecodable || w.toLong() * h > MAX_PIXELS) return null
        val source = decode(bytes) ?: return null
        return fit(source, type, maxEdge, maxBytes)
    }

    private fun decode(bytes: ByteArray): BufferedImage? =
        try { ImageIO.read(ByteArrayInputStream(bytes)) } catch (e: Exception) { null }

    private fun fit(source: BufferedImage, type: ImageType, maxEdge: Int, maxBytes: Int): Image? {
        val scale = minOf(1.0, maxEdge.toDouble() / max(source.width, source.height))
        val tw = max(1, (source.width * scale).roundToInt())
        val th = max(1, (source.height * scale).roundToInt())
        val scaled = resize(source, tw, th)
        if (type == ImageType.JPEG) return jpeg(scaled).takeIf { it.size <= maxBytes }?.let { Image(ImageType.JPEG, it, tw, th) }
        png(scaled).takeIf { it.size <= maxBytes }?.let { return Image(ImageType.PNG, it, tw, th) }
        return jpeg(scaled).takeIf { it.size <= maxBytes }?.let { Image(ImageType.JPEG, it, tw, th) }
    }

    /** Halves the image until one more halving would pass the target, then draws it at the target size (bilinear). */
    private fun resize(source: BufferedImage, tw: Int, th: Int): BufferedImage {
        var img = source
        do {
            val nw = if (img.width / 2 >= tw) img.width / 2 else tw
            val nh = if (img.height / 2 >= th) img.height / 2 else th
            img = draw(img, nw, nh, null)
        } while (nw != tw || nh != th)
        return img
    }

    private fun draw(img: BufferedImage, w: Int, h: Int, background: Color?): BufferedImage {
        val out = BufferedImage(w, h, if (background == null) BufferedImage.TYPE_INT_ARGB else BufferedImage.TYPE_INT_RGB)
        val g = out.createGraphics()
        try {
            g.setRenderingHint(RenderingHints.KEY_INTERPOLATION, RenderingHints.VALUE_INTERPOLATION_BILINEAR)
            g.setRenderingHint(RenderingHints.KEY_RENDERING, RenderingHints.VALUE_RENDER_QUALITY)
            if (background != null) {
                g.color = background
                g.fillRect(0, 0, w, h)
            }
            g.drawImage(img, 0, 0, w, h, null)
        } finally {
            g.dispose()
        }
        return out
    }

    private fun png(img: BufferedImage): ByteArray =
        ByteArrayOutputStream().also { ImageIO.write(img, "png", it) }.toByteArray()

    /** JPEG has no alpha: transparent parts become white. */
    private fun jpeg(img: BufferedImage): ByteArray {
        val rgb = draw(img, img.width, img.height, Color.WHITE)
        val writer = ImageIO.getImageWritersByFormatName("jpeg").next()
        val out = ByteArrayOutputStream()
        try {
            ImageIO.createImageOutputStream(out).use { stream ->
                writer.output = stream
                val param = writer.defaultWriteParam.apply {
                    compressionMode = ImageWriteParam.MODE_EXPLICIT
                    compressionQuality = JPEG_QUALITY
                }
                writer.write(null, IIOImage(rgb, null, null), param)
            }
        } finally {
            writer.dispose()
        }
        return out.toByteArray()
    }

    /** VP8 (lossy), VP8L (lossless) and VP8X (extended) headers. */
    private fun webpDimensions(b: ByteArray): Pair<Int, Int>? {
        fun u8(i: Int) = b[i].toInt() and 0xFF
        fun le16(i: Int) = u8(i) or (u8(i + 1) shl 8)
        fun le24(i: Int) = u8(i) or (u8(i + 1) shl 8) or (u8(i + 2) shl 16)
        if (b.size < 30) return null
        return when {
            b.has(12, 'V', 'P', '8', ' ') && b.has(23, 0x9D, 0x01, 0x2A) -> (le16(26) and 0x3FFF) to (le16(28) and 0x3FFF)
            b.has(12, 'V', 'P', '8', 'L') && u8(20) == 0x2F -> {
                val bits = u8(21).toLong() or (u8(22).toLong() shl 8) or (u8(23).toLong() shl 16) or (u8(24).toLong() shl 24)
                ((bits and 0x3FFF) + 1).toInt() to (((bits shr 14) and 0x3FFF) + 1).toInt()
            }
            b.has(12, 'V', 'P', '8', 'X') -> (le24(24) + 1) to (le24(27) + 1)
            else -> null
        }?.takeIf { (w, h) -> w > 0 && h > 0 }
    }
}

private fun ByteArray.has(offset: Int, vararg expected: Any): Boolean {
    if (size < offset + expected.size) return false
    return expected.withIndex().all { (i, e) ->
        val want = when (e) {
            is Char -> e.code
            is Int -> e
            else -> error("byte or char expected")
        }
        (this[offset + i].toInt() and 0xFF) == want
    }
}
```

```kotlin
package claudechat.image

/** An image waiting above the message box: validated bytes for Claude and a small [thumb] (`data:` URL, or "" when none could be made) for the page. */
class Attachment(val id: String, val name: String, val image: Image, val thumb: String)

/** One chat's attachments for its next message, in the order they were added. Not thread-safe: EDT only. */
class PendingAttachments(private val max: Int = Images.MAX_PER_MESSAGE) {
    private val items = LinkedHashMap<String, Attachment>()

    val size: Int get() = items.size

    /** False when [max] attachments are already waiting. */
    fun add(attachment: Attachment): Boolean {
        if (attachment.id !in items && items.size >= max) return false
        items[attachment.id] = attachment
        return true
    }

    fun remove(id: String) {
        items.remove(id)
    }

    /** Removes and returns the attachments with these ids, in the given order; unknown ids are skipped. */
    fun take(ids: List<String>): List<Attachment> = ids.distinct().mapNotNull { items.remove(it) }

    fun clear() = items.clear()
}
```

```kotlin
package claudechat.image

import java.io.ByteArrayOutputStream
import java.util.Base64

/**
 * Images arriving from the page as base64 chunks (one bridge message each). Each chunk is decoded on arrival, so a
 * chunk's length must be a multiple of 4 (the page sends 262144 characters). Not thread-safe: EDT only.
 */
class Uploads(private val maxBytes: Int = Images.MAX_INPUT_BYTES) {
    private class Upload(val name: String) {
        val bytes = ByteArrayOutputStream()
    }

    private val active = HashMap<String, Upload>()

    val count: Int get() = active.size

    fun has(id: String): Boolean = id in active

    fun start(id: String, name: String) {
        active[id] = Upload(name)
    }

    /** Appends a chunk. False — and the upload is dropped — when it is not base64 or the total would pass the cap. */
    fun chunk(id: String, base64: String): Boolean {
        val upload = active[id] ?: return false
        val bytes = try {
            Base64.getDecoder().decode(base64)
        } catch (e: IllegalArgumentException) {
            active.remove(id)
            return false
        }
        if (upload.bytes.size() + bytes.size > maxBytes) {
            active.remove(id)
            return false
        }
        upload.bytes.writeBytes(bytes)
        return true
    }

    /** The name and bytes of a complete upload, or null when it is unknown (refused, cancelled or never started). */
    fun finish(id: String): Pair<String, ByteArray>? = active.remove(id)?.let { it.name to it.bytes.toByteArray() }

    fun cancel(id: String) {
        active.remove(id)
    }

    fun clear() = active.clear()
}
```

## Decisions on points the spec leaves open

| Point | Decision |
|---|---|
| Bridge transport for 5 MB images (base64 ≈ 6.7 MB) | Chunked page → IDE upload: `attachStart` (id, name, size), `attachChunk` × n (262144 base64 characters each, decoded on arrival), `attachEnd`; raw input capped at 20 MB (checked from `size` before any bytes move, and again while decoding). JCEF can run out of process over Thrift with frame/message limits, and one 6.7 MB query string per image would also sit in several copies on both sides. |
| IDE → page size | Every image the page gets is a display copy (thumbnails ≤ 160 px / 64 KB, tool and markdown images ≤ 800 px / 512 KB); `reset` is split into `reset` + `items` batches of ≤ 2 000 000 characters. |
| WebP (the JDK has no WebP reader; the IDE's bundled WebP plugin adds one) | Run-time check `Images.webpDecodable`: with a reader, WebP is scaled and re-encoded as PNG (then JPEG) like GIF; without one, accepted as-is when ≤ 5 MB and ≤ 2000 px (header-parsed size), else refused (`WebP images over 5 MB or 2000 px can't be downscaled here`), and previews are the original when within the display cap, else `[image]`. |
| GIF that needs scaling and is still too large as PNG | Falls back to JPEG q=0.85 like PNG (spec only says "re-encoded as PNG"); animation is lost when scaled. |
| JPEG that needs scaling | Stays JPEG at q=0.85. |
| Image larger than 5 MB but within 2000 px | Re-encoded at its size (PNG/GIF → PNG, then JPEG; JPEG → JPEG q=0.85); refused if still over 5 MB. |
| Decompression bombs | Header dimensions are checked first; more than 40 megapixels is refused without decoding (`the image is too large to process`). |
| Order of blocks sent to the CLI | Text block first, then image blocks — the order the probe verified. The text block is omitted when the message has no text and no IDE notes. |
| Where pending attachments live | In Kotlin (`Chat.attachments`, EDT). The page only knows ids and thumbnails; `send` carries the ids. A page reload (`ready`) clears them; closing a chat clears them. |
| Who enforces the 10-image limit | Kotlin (`attachStart`, picker, and `PendingAttachments.add`), counting attachments being uploaded or prepared; the page does not count. |
| Sending while an image is still being prepared | The page ignores Send until every tile is ready (× removes a stuck one). |
| Non-image files dropped or picked | Read (if ≤ 20 MB) and refused by magic bytes with a notice; nothing reaches the CLI or the page. |
| Notice wording | `Couldn't attach <name>: <reason>.`, shown as an error notice in the chat log (kept in the chat's history). |
| Tab title of an image-only first message | `<label> · [image]`. |
| Transcript placeholder layout | One `[image]` per image, space-separated, on its own line above the typed text (bubble order); an image-only message shows just the placeholders. |
| Thumbnails in the bubble | Kept in `ChatItem.UserText.images` (≤ 64 KB each) so a page reload shows them again; never persisted. |
| Tool-result image conversion thread | The CLI reader thread inside `ChatSession` (under the session lock; never the EDT). Undecodable blocks show `[image]`. |
| Local image paths | Raw `token.href`; `<…>` unwrapped, `decodeURI`d, `./` dropped; any URL scheme or `//host` never leaves the page; any `..` segment is refused in Kotlin even when the target would be inside the project; at most 20 paths per reply. |
| Local image resolution timing | Only when a reply has finished streaming (like `resolvePaths`); alt text while streaming; asked again on every re-render (nothing cached). |
| Empty alt text | Rendered as an empty span (no visible text) when unresolved. |
| Marker spoofing | The marker includes a per-page-load random nonce (`crypto.getRandomValues`), so model text cannot forge one; markers are only ever replaced by `h()` elements. |
